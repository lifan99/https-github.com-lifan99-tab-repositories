# 模块 2｜Python import、对象与配置

预计 14 分钟 · 时间段 10–24 分钟

### 导入、定义和调用分开看

首次通常导入模块时，Python 执行模块顶层代码，并在 `sys.modules` 缓存模块；后续通常导入复用缓存。`from ... import name` 将当时找到的对象绑定到导入方名称，源模块后来重新赋值，不会自动更新这个绑定。

执行 `def` 创建函数对象，通常不执行函数体；执行 `class` 会执行类体并创建类对象。对本项目的数据类调用 `Class(...)` 才创建实例。不要把定义类理解为“类体内的代码都不会执行”。

### 名称引用和配置快照

赋值绑定对象引用，浅复制只复制外层容器。[E01_objects.py](examples/E01_objects.py) 展示两个不同列表仍共享内部字典的情况。本项目结果用 `tuple`、响应对象用 `frozen dataclass`，限制外层修改与字段赋值；它们不会递归冻结任意嵌套对象。

`Settings.from_env()` 读取、清理、校验环境变量，再生成 live 后端启动时的配置快照。直接 Settings(...) 会执行 __post_init__ 的时间校验，但不会执行 from_env 中的供应商、凭据与 URL 校验；类型标注也不代替运行时检查。`api_key` 的 `repr=False` 仅隐藏常规对象表示中的字段，不是加密。

```text
environment.py：将项目 .env 加载到进程环境，override=False
config.py     ：读取进程环境 → 清理与校验 → Settings

通常优先级：已有进程值 → .env → 代码默认
```

已有进程值包括空字符串；阶段模型另有 `or model` 的空白回退。修改 `.env` 后，进程中原有值可能继续保留，应检查 shell 覆盖并重启实际读取配置的后端；UI 有自己的 APISettings。

按需查 [Python 语法](../代码与指令参考指南.md#python)、[配置对象](../从零手撕多智能体审查项目.md#s08)和[环境加载](../从零手撕多智能体审查项目.md#s09)。

## 模块 3｜依赖注入与 Protocol

预计 12 分钟。工作流依赖一个可等待的方法，鉴权和 HTTP 解析由具体客户端处理。

真实接口节选：

```python
class AsyncLLMClient(Protocol):
    async def complete(self, *, model: str, messages: list[dict[str, str]]) -> str: ...
```

Protocol 描述方法形态，不要求实现继承它，也不自动执行运行时检查。缺少方法会在调用处出错，当前内核会将客户端普通异常归一为安全的模型失败。

依赖注入是从外部提供协作对象。服务资源工厂传入 live 客户端或 DemoClient，测试提供 AsyncMock 或异步 fake，三者复用相同业务内核。[E02](examples/E02_protocol.py) 使用同步独立接口演示概念，不能把它的同步实现直接传入业务内核。

on_response 是可选同步回调，传函数对象而非立即调用后的返回值。当前 UI 不使用内核展示回调，完整 HTTP 响应后才渲染；E05 的打印回调属于脚本路径。

## 模块 5｜数据流、契约与循环不变量

预计 22 分钟。Agent 是名称与提示词对象，没有自己的常驻线程。正常审核调用三次模型，多角色不自动保证质量。

输入先经 ReviewRequest 校验：非空白、最多 20,000 Python 字符，模式 logic/evidence，原文保持原样。completed 保存有效回答，context 给后序模型，ReviewRecord 保存阶段、状态、错误和最终报告。

| 即将调用 | context 键 | 已有有效回答 |
| --- | --- | --- |
| Analyst | original_input、review_mode | 无 |
| Critic | 再加 analyst_output | A |
| Judge | 再加 critic_output | A、C |

业务主循环的阅读顺序：

```text
阶段 running → 构造 system/user → 在模型预算内 await complete
  → 记录 raw_output → 非空检查 → Judge 严格解析
  → 总期限检查 → completed.append → 更新 context
  → 可选回调 → 期限检查 → 阶段 succeeded
全流程成功 → 发布 final_review → ReviewResult
```

Judge JSON 还需精确字段、枚举、类型、引用和跨字段规则合法。quote 必须等于未改写的 original_input[start:end]，坐标按 Python Unicode 字符，拒绝 bool 与越界。合法引用不保证解释正确。

第 k 轮开始前，completed 恰有前 k 份有效回答且有序，context 有原文、模式和前 k 份输出。初始化为空回答，成功轮次增加一项，正常终止得到三份；异常按发生位置分析，不能套用正常成功结论。

final_response 保留 Judge JSON 字符串，record.final_review 才是结构化对象。Judge 契约失败时 raw_output 单独保留，未进入有效回答；最终报告为空。

运行 [E05](examples/E05_project_trace.py)，核对模式键、JSON 与回调顺序；随后运行第二日非法引用演示。

## 模块 6｜错误、期限与部分结果

预计 14 分钟。按层追踪错误，不把页面渲染和模型故障混为一谈：

```text
传输故障 → LLMError → WorkflowError（阶段、有效回答、记录）
  → ServiceError → API FailureResponse → UI 保存与展示
Judge 契约失败 → invalid_output → 同一失败链
UI 网络结果未确认 → APIClientError → 保存 pending 标识
UI 渲染异常 → 保留已收结果，可重跑恢复
```

| 场景 | 模型调用数 | 保留的有效回答 |
| --- | --- | --- |
| 输入非法 | 0 | 无 |
| Analyst 模型失败 | 1 | 无 |
| Critic 模型失败 | 2 | A |
| Critic 内核回调失败 | 2 | A、C |
| Judge 模型失败或契约非法 | 3 | A、C |

回调在有效回答被记录之后发生，所以普通回调失败仍保留当前回答，但不会发布最终报告。内核和服务的意外异常按各层边界处理，不能靠错误文案猜原因。

网络操作、单次模型、整次审核默认预算分别 60、60、150 秒，错误为 network_timeout/model_timeout/total_timeout。总期限不在角色间重置，内核 slots 排队也计时；HTTP 服务满载立即拒绝，不排队。

外部取消更新快照，停止后续角色，清理后重新抛 CancelledError，调用方从独立 ReviewRun 查看部分结果。期限和取消采用协作机制，清理可能超出预算，不能证明供应商停止生成或计费。

运行 [E06](examples/E06_project_failure.py) 与 [D3 E04](../day-03/examples/E04_integrated_reviews.py)；分别区分模型失败、期限与外部取消。

## 模块 7｜AsyncMock、pytest 与验证证据

预计 14 分钟。只断言最终文本会漏掉角色被跳过、模型选择错误或上下文缺失。测试应约束次数、顺序、提示词、消息、状态、错误与结果。

独立课堂测试，调用当前内核，不联网：

```python
from unittest.mock import AsyncMock, Mock
import pytest
from review_system.clients import LLMError
from review_system.workflow import WorkflowError, run_review

def test_critic_failure_keeps_analyst():
    client = Mock(complete=AsyncMock())
    client.complete.side_effect = ['A', LLMError('synthetic failure')]
    with pytest.raises(WorkflowError) as caught:
        run_review('U', client, analyst_model='a', critic_model='c', judge_model='j')
    assert caught.value.agent == 'Critic'
    assert [r.content for r in caught.value.completed] == ['A']
    assert client.complete.call_count == 2
    assert caught.value.record.final_review is None
```

AsyncMock 提供可等待方法，side_effect 控制值或异常。patch 要替换名称实际查找的位置：urllib 教学类替换 clients.urlopen，业务 HTTPX 使用 mock transport。ASGI 测试走真实路由但不监听；lifespan 要显式管理。

```bash
.venv/bin/python -m pytest -q tests/test_workflow.py
.venv/bin/python -m pytest -q docs/two-hour-course/examples/E07_test_workflow.py
```

参数化会把一个测试函数展开为多个用例，不用函数数目猜通过数量。默认 tests/、课堂额外测试和 HTTP 参考练习分开记录。

## 模块 8｜Streamlit、按钮与 rerun

预计 8 分钟。当前 UI 在按钮分支发本地 API 请求，响应完成后统一保存和展示；普通 rerun 从 session_state 恢复，不能根据两次执行都调用展示函数断定重复渲染。

| 操作 | 当前行为 |
| --- | --- |
| 打开、编辑但未提交 | 不发审核请求，旧结果仍对应上一轮 |
| 点击 Review | 清旧结果，验证输入与 API 配置，生成或复用请求标识 |
| 成功 / 业务失败响应 | 保存全部或部分结果、阶段与报告/错误 |
| UI 网络结果未确认 | 保留 pending 标识，不自动重试 |
| 渲染失败 / 普通重跑 | 已收到结果留在会话，可恢复展示，无新模型调用 |

当前没有停止按钮、逐阶段推送、持久化历史查询或输入快照的完整可视关联。同标识只防止执行中重复，完成后再提交可能重新调用模型。

## 模块 9｜开发规则与业务能力

预计 6 分钟。开发工具可通过获准的工作区工具编辑文件和执行测试；本项目的 Agent 只是角色提示词对象，没有文件工具、任意规划或长期记忆。

harness 指围绕模型组织上下文、工具、状态与生命周期的运行程序，能力取决于具体实现。当前业务程序只组织固定评审链；使用同一个“Agent”词不代表有开发工具的能力。

AGENTS.md 是开发约定：保持简单、环境变量 Key、只改 mvp、测试工作流、运行 pytest、不引入数据库与 Docker。它不是输入校验器或权限沙箱；实际约束需由源码、测试与执行环境实现。

协作请求应写触发条件、改动范围和验证标准，避免只说“更专业”。模板见 [教程第 16 节](../从零手撕多智能体审查项目.md#s16)。

# 参考答案

## Q01–Q04：入口、导入与配置

Q01：导入绑定名称，方法执行时才发请求。两段为 UI→本地 API、后端→模型供应商。

Q02：复用 run_review_async；同步脚本使用薄封装 run_review 或 runtime 管理资源，已有事件循环直接 await 异步入口，不能嵌套 asyncio.run。

Q03：from 模块 import CONFIG 绑定当时对象；源模块重新赋值不自动更新该绑定，原地修改共享可变对象则可能双方可见。

Q04：已有进程值 old 优先。直接 Settings 构造只执行其 __post_init__ 时间校验；from_env 还读取和校验供应商、Key、URL、模型与环境值。应检查读取配置的后端进程。

## Q05–Q08：协议与异步

Q05：按对象方法协作，不要求继承 Protocol；内核 await complete，普通同步返回字符串不是可等待结果。

Q06：函数对象留待回调；带括号立即执行并传入返回值。当前 UI 没有把 display_response 传到内核，只在 HTTP 完成后显示。

Q07：HTTPX 主路径为 await http_client.post；urllib 教学类为 urlopen。内层 JSON 组织原文/模式/前序输出，外层满足供应商接口格式。

Q08：得到协程对象而不是文本。C 依赖 A、J 依赖 A/C，不能并行启动；并发发生在独立审核间。

## Q09–Q12：状态、失败与取消

Q09：completed 有 A/C 两个 AgentResponse；context 有 original_input、review_mode、analyst_output、critic_output，没有 judge_output。

Q10：第 k 轮前有前 k 个有效结果和对应上下文。初始化、成功追加与正常终止建立性质；Critic 回调发生在记录后、阶段成功前，因此有两份结果但仅 A 成功，J 未启动。

Q11：模型失败留 A，回调失败留 A/C，J 均不启动。页面渲染在服务已响应后发生，不能倒过来停止已完成审核，已有结果可重跑恢复。

Q12：分别约束网络操作、单次调用和整份审核，错误码不同。取消只是请求，等待任务才能确认退出和清理，最后快照从 ReviewRun 读取。

## Q13–Q16：测试与 UI

Q13：会漏掉跳过角色、模型名错或缺上下文。应断言调用 3 次、有序角色模型和独立提示词、上下文精确、报告字段与状态正确。

Q14：patch adapter.send，因为调用方查找的是已绑定的名称；实际导入方式改变时需重新核对。

Q15：点击按钮才发请求；新审核清旧结果，普通重跑读会话。页面渲染发生在 HTTP 响应之后，内核回调则发生在角色之间。

Q16：仍为上一轮结果；pending 标识只防执行中重复，前次结束后重用会重新运行，不能保证只计费一次。

## Q17–Q20：规则与验收

Q17：不能，规则由 ReviewRequest、HTTP DTO 和输入控件实际执行；开发约定不是运行时校验器。

Q18：角色对象只包含提示词，工作流没有文件工具或工具执行循环；开发环境的工具能力不会自动传给聊天 API。

Q19：例如输入可视关联，范围为页面状态与 UI 测试。断言编辑未提交不增请求、旧材料仍可辨认；新审核失败后部分结果关联新材料，不残留旧报告。

Q20：描述按钮、APISettings/标识、HTTP、DTO、Service、异步三阶段、契约、公开响应、客户端核验与会话展示。证据来自源码、调用记录、业务与 UI 测试；fake 不证明真实账号或质量。

## P01 参考实现：独立同步练习

```python example=A01_pair_solution.py
from unittest.mock import Mock

def review_pair(text, client):
    if not isinstance(text, str):
        raise TypeError("text must be str")
    if not text.strip():
        raise ValueError("text must not be blank")
    analysis = client.complete(stage="analysis", text=text)
    critique = client.complete(stage="critique", text=analysis)
    return analysis, critique

client = Mock()
client.complete.side_effect = ["A", "C"]
assert review_pair("U", client) == ("A", "C")
assert [call.kwargs for call in client.complete.call_args_list] == [
    {"stage": "analysis", "text": "U"},
    {"stage": "critique", "text": "A"},
]
empty_client = Mock()
try:
    review_pair(" \n", empty_client)
except ValueError:
    empty_client.complete.assert_not_called()
else:
    raise AssertionError("Expected ValueError")
print("两阶段教学练习验证通过")
```

## P02 参考测试：实际内核的异步替身与同步回调

```python example=A02_test_callback_solution.py
import json
from unittest.mock import AsyncMock, Mock
import pytest
from review_system.workflow import WorkflowError, run_review

def test_critic_callback_failure():
    client = Mock(complete=AsyncMock())
    judge_text = json.dumps({
        "summary": "Synthetic review", "verdict": "pass", "findings": [],
        "limitations": ["Offline teaching example."],
    })
    client.complete.side_effect = ["A", "C", judge_text]
    original_error = RuntimeError("private-detail")
    callback = Mock(side_effect=[None, original_error])
    with pytest.raises(WorkflowError) as caught:
        run_review(
            "U", client,
            analyst_model="a", critic_model="c", judge_model="j",
            on_response=callback,
        )
    assert caught.value.agent == "Critic"
    assert [item.content for item in caught.value.completed] == ["A", "C"]
    assert client.complete.call_count == 2
    assert callback.call_count == 2
    assert caught.value.__cause__ is original_error
    assert "private-detail" not in str(caught.value)
```

回调在 Critic 阶段失败，因此 Judge 不执行；合法 Judge 替身保留是为了与成功契约一致。业务测试还会断言失败状态与最终报告为空。

## P03 参考测试：urllib 教学类请求

```python example=A03_test_request_solution.py
from io import BytesIO
import json
from unittest.mock import patch
from review_system.clients import OpenAICompatibleClient
from review_system.config import Settings

def test_request_contract():
    settings = Settings("qwen", "https://example.invalid/v1", "synthetic-key", "m", "m", "m", "m", 12)
    messages = [{"role": "user", "content": "U"}]
    response = BytesIO(b'{"choices":[{"message":{"content":"OK"}}]}')
    with patch("review_system.clients.urlopen", return_value=response) as send:
        assert OpenAICompatibleClient(settings).complete(model="chosen", messages=messages) == "OK"
    request = send.call_args.args[0]
    assert request.full_url == "https://example.invalid/v1/chat/completions"
    assert request.get_method() == "POST"
    assert request.get_header("Authorization") == "Bearer synthetic-key"
    assert json.loads(request.data) == {"model": "chosen", "messages": messages, "stream": False}
    assert send.call_args.kwargs["timeout"] == 12
```

本测试仅验证保留的同步类；业务主路径请求验证位于 tests/test_async_clients.py。

## P04 参考提案

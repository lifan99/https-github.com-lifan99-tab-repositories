## 起点与今日目标

现有主路径为 Streamlit → UI HTTP 客户端 → FastAPI → ReviewService → 异步工作流 → 模型客户端。FastAPI、Pydantic、HTTPX 和 Uvicorn 已声明在 [pyproject.toml](../pyproject.toml) 中；环境安装与精确依赖见 [README](../README.md#快速开始)。

今天要能追踪 `GET /healthz` 与 `POST /api/v1/reviews`，解释一个 POST 如何等待审核完成，再返回三阶段回答和报告，或错误与部分结果。服务使用同一份异步内核，按单 worker 运行，每个服务实例容量为 2，满载立即拒绝。

先能解释 D2 合法/非法报告和 D3 超时、取消、资源回收，再进入服务层。练习使用 fake、内存测试和本机监听，不要求真实凭据；要保留实验可放在 `mvp/.tmp/d4-learning/`，不替换业务服务或修改历史证据。

## T4：推演 ReviewService 的准入边界

阅读 [service.py](../review_system/service.py) 和 [test_service.py](../tests/test_service.py)。Service 管理准入、活动标识和任务，不导入 Streamlit 或抛 FastAPI 专用异常。

- [ ] 定位 `CAPACITY = 2`、`_active`、`_tasks` 和 `_closing` 的职责。
- [ ] 追踪 `review()` 创建审核任务、保存总截止时间并跟踪任务的顺序。
- [ ] 在 `_execute` 中找到无 `await` 的准入段：先查关闭，再查重复标识，再查容量，最后登记接受的请求。
- [ ] 解释为何满载时，执行中标识的重复请求优先报 `duplicate_request`，新标识才报 `capacity_exceeded`。
- [ ] 找到独立 `review_id` 和 `ReviewRun` 的创建；被拒绝的请求不能得到审核结果或释放别人的标识。
- [ ] 对照 `finally` 与父请求清理，解释正常、失败和取消如何释放本次拥有的资源。
- [ ] 找到完成后同一 `request_id` 重新执行并得到新 `review_id` 的断言。

**与 D3 的区别：**D3 直接调用内核时可共享信号量并排队；HTTP 服务选择满载立即拒绝。服务不向内核重复传同一容量名额，也没有后台队列或跨进程协调。多 worker 会让每个实例各自拥有容量和标识，当前运行命令必须使用一个 worker。

验收：画出两份审核占满时的第三份新请求、重复请求与取消后再提交时间线；拒绝请求新增模型调用数为 0。

## T5：追踪两个路由与错误映射

- [ ] `GET /healthz` 返回 200 和运行模式；这只说明本地服务存活，不证明供应商可用或审核质量可靠。
- [ ] `POST /api/v1/reviews` 使用严格请求模型，`await service.review(...)` 等待完成，没有在路由里重写三角色逻辑。
- [ ] 找到请求校验与坏 JSON 的错误处理，核对公开错误不回显原文、凭据或堆栈。
- [ ] 找到 `ServiceError` 到 `error_response` 的转换，说明阶段记录和部分结果怎样进入失败响应。
- [ ] 核对成功响应包含三个有序回答、成功阶段和有效报告；非法报告不能进入成功响应。
- [ ] 找到固定 500 信息与关闭拒绝 503，不能把所有异常都归为用户输入或供应商错误。

| 结果 | HTTP | 错误码或关键行为 |
| --- | --- | --- |
| 审核完成 | 201 | `status=succeeded`，`error=null` |
| 请求不符合契约 | 422 | `invalid_request`，模型调用 0 次 |
| 相同请求仍执行中 | 409 | `duplicate_request`，模型调用 0 次 |
| 本地审核名额已满 | 429 | `capacity_exceeded`，模型调用 0 次 |
| 模型调用失败、输出不合格 | 502 | `model_error` / `invalid_output` |
| 网络、模型、审核总期限 | 504 | `network_timeout` / `model_timeout` / `total_timeout` |
| 内部程序或响应契约缺陷 | 500 | `internal_error`，固定公开信息 |
| 关闭时拒绝新审核 | 503 | `service_unavailable` |

验收：上游 401/429/503 在本地映射为 502/model_error；只有本地容量满才是 429/capacity_exceeded。普通工作流 502/504 保留阶段和有效回答；内部 500 不保证能恢复完整阶段详情。

## T6：验证取消、预算与资源恢复

- [ ] 核对服务从有效请求进入时保存截止时间，调度延迟不重新获得一份完整预算，内核沿用更早期限。
- [ ] 说明总预算不含请求上传与响应网络传输；UI 等待由独立的 `APISettings` 管理。
- [ ] 工作流失败时最终报告为空；非法 Judge 原始文本只留在失败阶段记录。
- [ ] 在父任务取消、任务尚未开始就被取消、关闭服务的测试中，找到任务收拢、活动标识和名额恢复断言。
- [ ] 找到取消一份审核后另一份继续完成的证据，以及共享传输关闭前审核清理已完成的断言。
- [ ] 明确当前没有页面停止按钮，测试取消 handler Task 不等于验证真实客户端断连取消；连接断开时也不承诺能返回错误正文。

验收：能用 `test_parent_cancel_before_child_starts_leaves_no_registration` 与 `test_service_passes_original_deadline_through_scheduling_delay` 解释早期取消和调度延迟两种容易遗漏的路径。

## T7：API 回归与本机 fake 演示

阅读已有 [test_service.py](../tests/test_service.py)、[test_api.py](../tests/test_api.py)。测试在模型边界注入替身，保留真实路由、校验、服务与工作流。同步 `with TestClient(app)` 触发 lifespan；异步 ASGI transport 测试显式进入同一应用的 lifespan。

| 场景 | 应定位的断言 |
| --- | --- |
| healthz、合法 POST | 模式正确、0 / 3 次模型调用、有序角色与有效报告 |
| 原文、模式、标识、未知字段、坏 JSON 非法 | 422、安全正文、0 次模型调用 |
| 活动重复与满载 | 分别 409 / 429，重复检查优先，拒绝者不占名额 |
| 上游状态、连接、协议错误 | 502，不泄露正文，已有有效回答保留 |
| Judge 非法输出 | 502/invalid_output，报告为空，原始失败文本单独记录 |
| 三类超时 | 都为 504，错误码区分 |
| 取消或失败后重用 | 标识与名额恢复，无关审核继续 |
| 完成后同标识再提交 | 新 review_id，重新执行 |
| 内部缺陷、无效 live 配置、独立应用 | 固定 500、启动明确失败、应用状态互不污染 |
| 服务关闭 | 收拢任务后再关闭共享 HTTP 客户端 |

```bash
.venv/bin/python -m pytest -q tests/test_service.py tests/test_api.py tests/test_api_client.py
PYTHONPATH=. .venv/bin/python docs/day-04/examples/E03_local_http_smoke.py
.venv/bin/python -m pytest -q
```

E03 自动启动本机临时端口，验证 201、422 与 504 并关闭。ASGI 内存测试没有真实监听；E03 是真实本机 HTTP，但模型仍是 fake，不请求供应商。

也可手动启动现有服务。在项目根目录执行：

```bash
REVIEW_EXECUTION_MODE=fake .venv/bin/python -m uvicorn review_system.api:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

另开终端，在服务运行期间执行：

```bash
curl -i http://127.0.0.1:8000/healthz
curl -i http://127.0.0.1:8000/api/v1/reviews \
  -H 'Content-Type: application/json' \
  --data '{"request_id":"day4-demo-001","original_input":"仅用内存保存记录，重启后历史仍在。","review_mode":"logic"}'
```

预期为 200/fake 和 201/fake，POST 返回三个演示回答和 `insufficient_evidence` 报告。这是预置输出，不是对材料的真实判断。接口文档位于本地 `/docs`；结束后在服务终端按 Ctrl+C。

当前 UI 已接入此接口，可在服务运行时另开终端体验：

```bash
REVIEW_API_BASE_URL=http://127.0.0.1:8000 .venv/bin/python -m streamlit run app.py --server.address 127.0.0.1
```

页面显示 fake 标识，并在 HTTP 返回后统一展示。完整 UI→HTTP→API 自动演示见 [D5 脚本](day-05/examples/E01_ui_http_smoke.py)，可按需另行运行；该脚本与 API 内存测试的验证范围不同。

## 今日目标与范围

解释为什么“模型返回非空文本”不足以构成最终报告；追踪现有解析器如何检查 JSON、字段、枚举、原文引用和跨字段规则；用离线实验观察合法报告被接受、非法报告被拒绝及部分结果被保留。

Analyst、Critic 仍返回非空文本；Judge 返回严格 JSON。`logic` 和 `evidence` 都只评估所给材料，引用校验不等于事实核验。当前不含 RAG，知识库证据可留到后续扩展契约时学习。

## T7：运行回归与两条演示

先预测以下场景，再定位已有测试断言。已有测试充分覆盖的行为不需要重复新增测试。

| 场景 | 必须观察到的行为 |
| --- | --- |
| 合法三阶段输出 | 调用 3 次，上下文完整，报告可读，阶段全部成功 |
| 空白、非字符串、超长或非法模式 | 模型调用 0 次 |
| 恰好 20,000 字符 | 原文完整进入上下文 |
| Judge 围栏、重复键、非标准常量、字段或类型错误 | 拒绝，最终报告为空 |
| 引用越界、布尔值坐标、摘录不匹配 | 拒绝，不进行隐式修正 |
| 中文、换行、重复片段的正确引用 | 按原文 Python 字符位置通过 |
| 结论与问题、限制冲突 | 按跨字段规则拒绝 |
| Critic 模型失败 / 内核回调失败 | 分别保留 1 / 2 个有效回答，Judge 跳过 |
| Judge 契约失败 | 保留前两阶段，非法原始输出单独记录 |
| 页面重跑、连续审核与渲染失败 | 不重复请求、不混入旧报告、已收结果可恢复 |

```bash
.venv/bin/python -m pytest -q tests/test_contracts.py tests/test_workflow.py tests/test_app.py
PYTHONPATH=. .venv/bin/python docs/day-02/examples/E01_contract_review.py
PYTHONPATH=. .venv/bin/python docs/day-02/examples/E01_contract_review.py --invalid-quote
.venv/bin/python -m pytest -q
```

两个演示都调用 3 次 fake 模型。合法演示显示 `needs_revision` 和三个成功阶段；非法引用演示断言错误码为 `invalid_output`，并显示引用错误、保留 2 个有效回答、阶段为 `succeeded / succeeded / failed`。前者的有效负面结论仍然是一次成功审核。

## 2. 环境与命令格式

### 2.1 首次准备环境

已有可用 `.venv` 时跳过创建步骤。

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-py312-linux.txt -e '.[test,dev]'
.venv/bin/python scripts/check.py
```

安装依赖需要访问包源。`-e` 表示以可编辑方式安装本项目；`[test,dev]` 同时安装测试与检查工具；精确版本清单已在 Linux/Python 3.12 验证，其他平台见根 README。修改本地源码后，导入通常直接使用本地文件。

使用明确的 `.venv/bin/python`，可避免系统 Python、其他项目虚拟环境和本项目环境混用。无需先激活虚拟环境，也能运行本指南的命令。

### 2.2 常见命令符号

| 写法 | 含义 |
| --- | --- |
| `python -m pytest` | 由这个 Python 解释器运行 pytest 模块 |
| `python some_file.py` | 执行指定 Python 脚本 |
| `PYTHONPATH=. python ...` | 仅为这条命令添加当前目录到模块搜索路径 |
| `REVIEW_PROVIDER=deepseek ...` | 只为这次启动覆盖一个环境变量 |
| `-q` | 减少 pytest 输出 |
| `-x` | pytest 遇到第一项失败后停止 |
| `-k 'failure or callback'` | 按 pytest 测试名称表达式筛选 |
| `文件.py::测试函数名` | 选中一个测试函数；参数化函数可能有多项用例 |
| `<<'PY'` 到单独一行 `PY` | 把中间内容作为 Python 程序输入；引号阻止 Shell 展开正文 |
| 行末 `\` | Bash 命令换行继续，反斜线后不要加空格 |

本指南中的 Bash 命令在终端运行，Python 代码在 Python 解释器或脚本中运行。不要把 `pip install`、`curl` 等终端命令直接粘进 Python 的 `>>>` 提示符。

## 3. 配置与真实运行

### 3.1 创建本地配置，保留已有文件

以下命令仅在 `.env` 不存在时创建它；已有文件保持原样：

```bash
.venv/bin/python - <<'PY'
from pathlib import Path

try:
    with Path('.env').open('x', encoding='utf-8') as target:
        target.write(Path('.env.example').read_text(encoding='utf-8'))
except FileExistsError:
    print('.env 已存在，请直接在本机编辑。')
else:
    print('已创建 .env，请填写所选供应商的 API Key。')
PY
```

用编辑器打开项目根目录 `.env`，填写对应 Key。模板 [`.env.example`](../.env.example) 的 Key 是空值；真实凭据只留在环境或本机 `.env` 中，不粘贴到学习记录、代码或聊天模板里。

### 3.2 当前实际支持的环境变量

| 变量 | 当前作用 |
| --- | --- |
| `REVIEW_PROVIDER` | `qwen` 或 `deepseek`，默认 `qwen` |
| `QWEN_API_KEY` / `DEEPSEEK_API_KEY` | 所选供应商的凭据，不能为空 |
| `QWEN_BASE_URL` / `DEEPSEEK_BASE_URL` | 所选供应商的 API 根地址；客户端自动追加 `/chat/completions` |
| `QWEN_MODEL` / `DEEPSEEK_MODEL` | 默认模型名；当前代码默认分别为 `qwen-plus` / `deepseek-flash` |
| `ANALYST_MODEL` | Analyst 模型名；未设置或为空时使用供应商默认模型 |
| `CRITIC_MODEL` | Critic 模型名；规则同上 |
| `JUDGE_MODEL` | Judge 模型名；规则同上 |
| `REVIEW_TIMEOUT_SECONDS` | 后端 HTTPX 网络操作超时，默认 60 秒 |
| `REVIEW_MODEL_TIMEOUT_SECONDS` | 后端单次模型调用预算，默认 60 秒 |
| `REVIEW_TOTAL_TIMEOUT_SECONDS` | 后端整次审核预算，默认 150 秒，角色间不重置 |
| `REVIEW_EXECUTION_MODE` | 后端 live（默认）或显式 fake；fake 不需模型 Key |
| `REVIEW_API_BASE_URL` | UI 使用的本地 API 根地址，默认 http://127.0.0.1:8000 |
| `REVIEW_API_TIMEOUT_SECONDS` | UI HTTP 操作等待，默认声明的总预算加 30 秒，必须更大 |

模型名与端点的默认值来自当前源码，不代表你的账号或区域一定可用。角色模型覆盖仍使用同一个供应商、端点和 Key，不是分别配置三个供应商。

加载顺序：`load_project_env()` 加载项目根目录 `.env`，已有进程环境变量优先；`Settings.from_env()` 再读取并校验配置。已经存在但值为空的环境变量也会阻止 `.env` 覆盖。

模型供应商由后端选择。例如，以 DeepSeek 启动 live 后端（需本机已有有效配置）：

```bash
REVIEW_EXECUTION_MODE=live REVIEW_PROVIDER=deepseek .venv/bin/python -m uvicorn review_system.api:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

在另一个终端启动 UI，页面只需知道后端地址：

```bash
REVIEW_API_BASE_URL=http://127.0.0.1:8000 .venv/bin/python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

无凭据体验使用第 13.2 节的 fake 后端；只在 UI 环境修改 REVIEW_PROVIDER 不会改变已运行后端的供应商。前后端独立配置时需协调总预算，UI 不能探测另一进程的真实预算。

### 3.4 当前 UI 的行为

正常点击 Review 后由后端依次调用三个角色，HTTP 响应返回后统一展示阶段回答。当前请求设置 `stream=False`，没有逐 token 流式展示。发生模型错误时停止后续角色，保留本次已完成的回答；再次页面重跑可以恢复当前会话结果，服务重启后的历史恢复尚未实现。

D2 已加入 logic/evidence 模式、阶段状态与结构化报告；Judge 契约失败保留其未通过校验的原始文本，最终报告为空。两种模式都不进行外部事实核验。详见 [D2 实施记录](day-02-evidence.md)。D3 已迁移异步客户端并实现三层超时、并发隔离与取消，见 [D3 实施记录](day-03-evidence.md)。

## 5. 当前可调用的接口

### 5.1 异步内核与同步入口

以下为当前签名参考，省略函数体：

```python
async def run_review_async(
    user_input: str,
    client: AsyncLLMClient,
    *,
    analyst_model: str,
    critic_model: str,
    judge_model: str,
    review_mode: str = "logic",
    on_response: Callable[[AgentResponse], None] | None = None,
    model_timeout_seconds: float = 60,
    total_timeout_seconds: float = 150,
    total_deadline: float | None = None,
    slots: asyncio.Semaphore | None = None,
    run: ReviewRun | None = None,
    review_id: str | None = None,
) -> ReviewResult:
    ...
```

| 参数 | 说明 |
| --- | --- |
| `user_input` | 原始字符串；纯空白或超过 20,000 字符被拒绝；合法输入保持原样 |
| `client` | 提供异步 `complete(model=..., messages=...) -> str` 的对象 |
| 三个 `*_model` | 必须用关键字传入，可以相同，也可以不同 |
| `review_mode` | `logic`（默认）或 `evidence`；两个模式均只评估输入材料 |
| `on_response` | 可选同步回调，每次取得有效回答并记录后执行 |

同步脚本调用 `run_review(user_input, client, **kwargs)`；其内部使用一次 `asyncio.run`。已在事件循环中的调用方直接 `await run_review_async(...)`。两个入口都接受异步客户端，`request_id` 由 D4 Service 管理；内核新增可选 `total_deadline`，用于传递同一单调时钟截止时间。共享 `slots` 限制同一循环中的在途审核；`run` 必须每次新建，取消后从它读取最终快照。

### 5.2 返回对象与异常

| 名称 | 当前字段或属性 |
| --- | --- |
| `AgentResponse` | `agent`、`model`、`content` |
| `ReviewResult` | `responses`：角色回答元组；`record`：本次请求、阶段与最终报告 |
| `result.final_response` | 正常完成后取最后一个角色，即 Judge 的文本 |
| `LLMError` | 模型调用或返回内容错误，位于 `clients.py` |
| `WorkflowError` | `agent`、已完成回答 `completed`、失败记录 `record`，位于 `workflow.py` |
| `ValueError` | 工作流空白/超长输入或配置校验失败 |

`result.record.final_review` 是通过字段、枚举、原文引用和跨字段检查的结构化报告。`result.final_response` 返回 Judge 的原始 JSON 文本。错误的 `record.final_review` 为 `None`；Judge 契约失败时，原始文本在失败阶段的 `raw_output` 中，不能加入 `completed`。

### 5.3 每次模型调用的消息

每阶段发送两条消息：`system` 是该角色独立提示词，`user` 是下表字典经 `json.dumps(..., ensure_ascii=False)` 得到的字符串。

| 阶段 | 字典包含的键 |
| --- | --- |
| Analyst | `original_input`、`review_mode` |
| Critic | `original_input`、`review_mode`、`analyst_output` |
| Judge | `original_input`、`review_mode`、`analyst_output`、`critic_output` |

### 5.4 错误后的结果数量

| 情况 | 模型调用数 | 保留的回答 |
| --- | --- | --- |
| 空白或超长输入，直接调用工作流 | 0 | 无 |
| Analyst 模型失败 | 1 | 无 |
| Critic 模型失败 | 2 | Analyst |
| Critic 内核回调抛普通异常 | 2 | Analyst、Critic |
| Judge 模型失败 | 3 | Analyst、Critic |
| Judge 契约失败 | 3 | Analyst、Critic；原始 Judge 文本单独留在失败记录 |
| 全部成功 | 3 | Analyst、Critic、Judge |

内核回调失败时已经记录了当前回答，所以数量与模型失败不同。当前 UI 在完整 HTTP 响应后渲染，页面渲染失败不等于内核 callback_error；已收结果保留在会话。`KeyboardInterrupt` 等不属于普通 `Exception` 的异常继续传播；异步取消使用 `CancelledError`，清理后继续传播；最后记录可从 `ReviewRun` 读取。

## 6. 可以直接运行的代码模板

下面三段均在项目根目录复制运行，使用 Mock 替身，不读取 Key，也不请求真实模型。

### 6.1 成功路径：读取固定样例，检查上下文

```bash
.venv/bin/python - <<'PY'
import json
from pathlib import Path
from unittest.mock import AsyncMock, Mock
from review_system.workflow import run_review

original = Path('docs/samples/d1-logic-proposal.txt').read_text(encoding='utf-8')
client = Mock(complete=AsyncMock())
judge_text = json.dumps({
    'summary': '人工预置结论', 'verdict': 'insufficient_evidence',
    'findings': [], 'limitations': ['离线人工样例，没有核验外部事实。'],
}, ensure_ascii=False)
client.complete.side_effect = ['人工预置分析', '人工预置批评', judge_text]
result = run_review(
    original,
    client,
    analyst_model='fake-a',
    critic_model='fake-c',
    judge_model='fake-j',
    on_response=lambda response: print(response.agent, response.content),
)

contexts = [
    json.loads(call.kwargs['messages'][1]['content'])
    for call in client.complete.call_args_list
]
assert client.complete.call_count == 3
assert all(context['original_input'] == original for context in contexts)
assert contexts[1]['analyst_output'] == '人工预置分析'
assert contexts[2]['critic_output'] == '人工预置批评'
assert result.final_response == judge_text
assert result.record.final_review.verdict == 'insufficient_evidence'
print('上下文键：', [list(context) for context in contexts])
print('最终回答：', result.final_response)
PY
```

这里的回答由 `side_effect` 预先指定，用于验证程序行为，不评价模型审核质量。

### 6.2 模型失败：捕获错误与部分结果

```bash
.venv/bin/python - <<'PY'
from unittest.mock import AsyncMock, Mock
from review_system.clients import LLMError
from review_system.workflow import WorkflowError, run_review

client = Mock(complete=AsyncMock())
client.complete.side_effect = ['Analyst 已完成', LLMError('synthetic timeout')]
try:
    run_review(
        '演示输入', client,
        analyst_model='fake-a', critic_model='fake-c', judge_model='fake-j',
    )
except WorkflowError as exc:
    assert exc.agent == 'Critic'
    assert client.complete.call_count == 2
    assert [response.agent for response in exc.completed] == ['Analyst']
    print('失败阶段：', exc.agent)
    print('已完成：', [response.agent for response in exc.completed])
    print('模型调用次数：', client.complete.call_count)
else:
    raise AssertionError('预期出现 WorkflowError')
PY
```

这是人为抛出的错误，不是供应商真的超时。

### 6.3 内核回调失败：当前阶段回答仍被保留

```bash
.venv/bin/python - <<'PY'
from unittest.mock import AsyncMock, Mock
from review_system.workflow import WorkflowError, run_review

def display(response):
    if response.agent == 'Critic':
        raise RuntimeError('synthetic display failure')

client = Mock(complete=AsyncMock())
client.complete.side_effect = ['A', 'C', 'J']
try:
    run_review(
        '演示输入', client,
        analyst_model='fake-a', critic_model='fake-c', judge_model='fake-j',
        on_response=display,
    )
except WorkflowError as exc:
    assert [r.agent for r in exc.completed] == ['Analyst', 'Critic']
    assert client.complete.call_count == 2
    assert 'synthetic display failure' not in str(exc)
    print('已保留：', [r.agent for r in exc.completed])
    print('错误：', exc)
else:
    raise AssertionError('预期出现回调错误')
PY
```

### 7.2 isinstance 与 type：判断类型

`isinstance(value, 类型)` 判断值是否属于该类型或其子类。通常用它检查外部输入和模型返回值。`type(value) is 类型` 要求精确类型，在需要排除子类时使用。

```python
assert isinstance('审核文本', str)
assert isinstance(['A', 'C'], list)
assert isinstance({'agent': 'Judge'}, dict)
assert isinstance(1.5, (int, float))  # 元组表示允许多种类型。

assert isinstance(True, bool)
assert isinstance(True, int)         # bool 是 int 的子类。
assert type(True) is not int
assert type(3) is int

def is_nonblank_text(value):
    return isinstance(value, str) and bool(value.strip())

assert is_nonblank_text('  A  ')
assert not is_nonblank_text(None)
assert not is_nonblank_text(' \n\t')
assert not is_nonblank_text(123)
```

项目当前的输出检查正是先判断 `isinstance(content, str)`，再判断是否空白。D2 引用位置只接受整数而不接受 `true` 时，可用 `type(start) is int`。

不要写 `isinstance(values, list[str])`，带参数的泛型不能这样用于运行时检查，会抛 `TypeError`。应先检查 `isinstance(values, list)`，再逐项检查元素。类型标注 `values: list[str]` 也不会自动执行这些校验。

### 7.3 None、真假值、短路与 is / ==

`None` 表示缺失或没有结果；`False`、0、空字符串、空列表也都属于假值，但不等于它们都是 None。

```python
value = None
assert value is None
empty_text = ''
assert empty_text is not None
assert not bool('')
assert not bool([])
assert not bool(0)
assert bool('False')                 # 非空字符串，即使内容写着 False。

left, right = ['A'], ['A']
assert left == right                # 值相等。
assert left is not right            # 是两个不同对象。

content = None
invalid = not isinstance(content, str) or not content.strip()
assert invalid                      # 左侧已为真，不会执行 None.strip()。

configured_limit = 0
assert (configured_limit or 10) == 10
limit = 10 if configured_limit is None else configured_limit
assert limit == 0                   # 仅缺失时使用默认值，保留合法的 0。
```

比较字符串或数字内容通常用 `==`；判断 None 用 `is None`。`and` / `or` 会短路，而且返回参与运算的值，不一定返回布尔值。项目里角色模型名用 `覆盖值 or 默认模型`，是因为空字符串也应回退；其他字段不要照搬这个规则。

### 7.4 字符串：检查、拆分、拼接与格式化

```python
text = '  Analyst\nCritic  '
assert text.strip() == 'Analyst\nCritic'
assert text.startswith('  ')
assert text.endswith('  ')
assert 'Critic' in text
assert 'Analyst'.lower() == 'analyst'
assert 'qwen'.upper() == 'QWEN'
assert 'A,C,J'.split(',') == ['A', 'C', 'J']
assert 'A\nC\nJ'.splitlines() == ['A', 'C', 'J']
assert ' → '.join(['A', 'C', 'J']) == 'A → C → J'
assert 'fake-a'.replace('fake', 'demo') == 'demo-a'

agent, count = 'Critic', 2
message = f'{agent} 已完成；调用次数={count}'
assert message == 'Critic 已完成；调用次数=2'
assert f'{20_000:,}' == '20,000'
assert text == '  Analyst\nCritic  '  # 上面的字符串方法未修改原字符串。
```

字符串不可变，`strip()` 返回新字符串；只有赋值回原变量才会替换它。验证原文时可用 `text.strip()` 检查空白，但保留原始 `text`，否则会改变引用坐标。`join` 的元素必须是字符串；例如需要把数字连接时，可以写 `','.join(str(n) for n in [1, 2])`。

### 7.5 列表、元组、索引与切片

```python
completed = []
returned = completed.append('A')
assert returned is None
completed.extend(['C', 'J'])
assert completed == ['A', 'C', 'J']
assert len(completed) == 3
assert completed[0] == 'A'
assert completed[-1] == 'J'
assert completed[:2] == ['A', 'C']

snapshot = tuple(completed)
completed.pop()
assert completed == ['A', 'C']
assert snapshot == ('A', 'C', 'J')

original = '仅用内存保存记录，重启后历史仍在。'
assert original[9:16] == '重启后历史仍在'
assert original[100:] == ''          # 切片越界会截取可用部分，不自动报错。
```

`append(x)` 添加一个元素，`extend(xs)` 逐项添加多个元素；不要写 `completed = completed.append(x)`，因为 append 返回 None。

索引不存在会抛 `IndexError`，空列表也不能取 `[-1]`。切片则可能容忍越界，所以 D2 位置校验仍需显式检查 `0 <= start < end <= len(original)`。元组限制外层增删改，不会自动冻结其中的可变对象。

### 7.6 字典：取字段、默认值、更新与删除

```python
context = {'original_input': 'U'}
assert context['original_input'] == 'U'
assert context.get('analyst_output') is None
assert context.get('review_mode', 'logic') == 'logic'
assert 'original_input' in context   # 对字典使用 in，检查的是键。

context['analyst_output'] = 'A'
context.update({'critic_output': 'C'})
assert list(context.keys()) == ['original_input', 'analyst_output', 'critic_output']
assert dict(context.items()) == context
assert 'A' in context.values()
assert context.pop('critic_output') == 'C'
assert context.pop('not_present', None) is None

settings = {'model': None}
assert settings.get('model', 'fallback') is None
assert settings.get('missing', 'fallback') == 'fallback'
```

`d[key]` 缺键时抛 `KeyError`；`d.get(key, default)` 只在缺键时返回默认值，已有值为 None 时不会回退。`pop(key, None)` 可用于清除可能不存在的状态，当前 UI 就用它清除旧结果。字典会保留插入顺序，但业务规则应按字段名取值，不依赖 JSON 文本的键顺序。

### 7.7 集合：去重与查缺字段

```python
allowed = {'summary', 'verdict', 'findings', 'limitations'}
payload = {'summary': '说明', 'verdict': 'pass', 'extra': 1}
actual = set(payload)
missing = allowed - actual
unexpected = actual - allowed

assert missing == {'findings', 'limitations'}
assert unexpected == {'extra'}
assert sorted(missing) == ['findings', 'limitations']
assert len(set(['A', 'C', 'A'])) == 2
assert 'high' in {'low', 'medium', 'high'}
```

`set()` 才是空集合，`{}` 是空字典。集合不承诺固定遍历顺序，展示缺字段列表时可先 `sorted`。集合元素必须可哈希，例如字符串；不能直接把字典作为集合元素。

### 7.8 循环、配对、排序与统计

```python
roles = ['Analyst', 'Critic', 'Judge']
models = ['fake-a', 'fake-c', 'fake-j']
assert list(enumerate(roles, start=1))[0] == (1, 'Analyst')
assert list(range(3)) == [0, 1, 2]
pairs = list(zip(roles, models, strict=True))
assert pairs[-1] == ('Judge', 'fake-j')

lengths = [len(value) for value in ['A', 'CCC', 'JJ']]
assert sum(lengths) == 6
assert min(lengths) == 1
assert max(lengths) == 3
assert max([], default=0) == 0

rows = [{'agent': 'A', 'elapsed': 3}, {'agent': 'C', 'elapsed': 1}]
ordered = sorted(rows, key=lambda row: row['elapsed'])
assert [row['agent'] for row in ordered] == ['C', 'A']
assert rows[0]['agent'] == 'A'        # sorted 返回新列表。
```

`enumerate` 同时给序号和值；`range` 的结束值不包含在结果内。默认 `zip` 遇到较短的一侧就结束，可能掩盖模型列表漏项；要求长度相同可用 `strict=True`，不一致时在迭代过程中抛 `ValueError`。`list.sort()` 原地排序并返回 None，和 `sorted()` 不同。`break` 结束当前循环，`continue` 跳过当前轮剩余语句；失败后需要整体停止时，不要误写成 continue。

### 7.9 推导式、all、any、next

```python
responses = [
    {'agent': 'Analyst', 'content': 'A'},
    {'agent': 'Critic', 'content': ''},
    {'agent': 'Judge', 'content': 'J'},
]
names = [item['agent'] for item in responses]
nonempty = [item for item in responses if item['content']]
by_agent = {item['agent']: item['content'] for item in responses}
assert names == ['Analyst', 'Critic', 'Judge']
assert len(nonempty) == 2
assert by_agent['Judge'] == 'J'
assert any(not item['content'] for item in responses)
assert not all(item['content'] for item in responses)
assert all([]) is True
assert any([]) is False

def is_nonempty_text_list(value):
    return (
        isinstance(value, list)
        and bool(value)
        and all(isinstance(item, str) and bool(item.strip()) for item in value)
    )

assert is_nonempty_text_list(['A', 'C'])
assert not is_nonempty_text_list([])
iterator = iter(['A'])
assert next(iterator, None) == 'A'
assert next(iterator, None) is None
```

`all([])` 为真，所以“每项合法”和“至少有一项”是两条规则。生成器表达式按需产出，迭代器读完不会自动回到开头。字典推导式的键若重复，后面的值会覆盖前面的值；它不是重复角色校验器。

### 7.10 赋值、浅拷贝与深拷贝

```python
from copy import deepcopy

original = {'outputs': ['A']}
alias = original
shallow = original.copy()
deep = deepcopy(original)
alias['outputs'].append('C')

assert alias is original
assert shallow is not original
assert shallow['outputs'] == ['A', 'C']
assert deep['outputs'] == ['A']

shallow['label'] = 'copy'
assert 'label' not in original
```

赋值让两个名称指向同一对象；浅拷贝只复制外层，内部列表仍共享。当前上下文主要保存不可变字符串，记录 `dict(context)` 通常足够；若以后加入嵌套列表，就要重新检查共享关系。并发审核应首先各自新建状态，不把 deepcopy 当作共享 HTTP 客户端的解决方式。

### 7.11 函数、参数、返回值与回调

```python
def make_response(content, *, agent='Analyst'):
    return {'agent': agent, 'content': content}

options = {'agent': 'Critic'}
assert make_response('C', **options) == {'agent': 'Critic', 'content': 'C'}

def collect(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

assert collect('A') == ['A']
assert collect('C') == ['C']

def emit(response, on_response=None):
    if on_response is not None:
        on_response(response)
    return response['content']

seen = []
assert emit(make_response('A'), on_response=seen.append) == 'A'
assert seen == [{'agent': 'Analyst', 'content': 'A'}]
```

`return` 把结果交给调用者并结束函数；`print` 用于显示，不代替返回值。回调传函数对象，例如 `on_response=display_response`，不要先写成 `display_response(...)` 把它立即执行。避免 `def collect(item, items=[])`：可变默认值会被多次调用共享。`*args` 收集位置参数，`**kwargs` 收集关键字参数；本项目固定的角色模型参数不需要为了灵活而全部改成 kwargs。

### 7.12 getattr、hasattr、callable：检查对象能力

```python
from types import SimpleNamespace

response = SimpleNamespace(agent='Analyst', content='A')
assert getattr(response, 'agent') == 'Analyst'
assert getattr(response, 'model', 'unknown') == 'unknown'
assert hasattr(response, 'content')
assert not hasattr(response, 'model')

client = SimpleNamespace(complete=lambda **kwargs: 'A')
assert callable(client.complete)
assert not callable(response.content)
assert client.complete(model='fake-a', messages=[]) == 'A'
```

`getattr(obj, name, default)` 按名称取属性；无默认值且属性缺失时抛 `AttributeError`。`hasattr` 只检查能否成功访问该属性，`callable` 只检查对象能否调用，都不保证方法参数或返回值符合协议。访问 property 时这些函数也可能执行 getter，不能把它们当成永远无副作用的结构扫描。已知接口的正常路径优先直接访问属性。

### 7.13 类型转换、异常与有限数值

```python
import math

assert int('12') == 12
assert float('1.5') == 1.5
assert str(12) == '12'

def positive_seconds(raw):
    try:
        value = float(raw)
    except (TypeError, ValueError) as exc:
        raise ValueError('秒数必须是数字') from exc
    if not math.isfinite(value) or value <= 0:
        raise ValueError('秒数必须是有限正数')
    return value

assert positive_seconds('60') == 60.0
for bad in ['abc', 'nan', 'inf', '0', '-1', None]:
    try:
        positive_seconds(bad)
    except ValueError:
        pass
    else:
        raise AssertionError(f'应拒绝：{bad!r}')
```

这段函数模拟环境变量文本的解析。若处理 JSON 中要求“精确数字类型”的字段，还要先排除布尔值，不能只做 `float(raw)`。例如 `float(True)` 会得到 1.0；`int(1.9)` 会截去小数部分，不适合作为严格整数校验。

`try` 放可能失败的操作，`except` 处理预期异常，`else` 在没有异常时执行，`finally` 用于退出清理。不要用空的 `except Exception: pass` 掩盖未知失败。示例中的 assert 用于学习检查与测试；对用户输入的正式校验应使用显式条件和 `raise`，因为优化模式可禁用 assert。

### 7.14 JSON：序列化不等于业务校验

```python
import json

payload = {'agent': 'Judge', 'valid': True, 'extra': None, 'items': ['结论']}
encoded = json.dumps(payload, ensure_ascii=False)
decoded = json.loads(encoded)
assert decoded == payload
assert '结论' in encoded
assert json.loads('null') is None
assert json.loads('[1, 2]') == [1, 2]

try:
    json.loads('{bad json}')
except json.JSONDecodeError:
    pass
else:
    raise AssertionError('应拒绝非法 JSON')

model_output = json.loads('{"verdict": "banana"}')
assert isinstance(model_output, dict)
assert model_output['verdict'] not in {'pass', 'needs_revision', 'insufficient_evidence'}
```

JSON 顶层可能是对象、数组、字符串、数字或 null，解析后必须继续检查类型。Python 的 `True` / `None` 在 JSON 中对应 `true` / `null`。不要用 `eval` 解析模型文本。D2 对重复键、非标准数值和引用一致性的进一步限制见 [第二日阅读材料](第二日阅读材料.md)。

### 7.15 dataclass、asdict 与 property

```python
from dataclasses import asdict, dataclass

@dataclass(frozen=True)
class Reply:
    agent: str
    content: str

    @property
    def is_nonempty(self) -> bool:
        return bool(self.content.strip())

reply = Reply('Analyst', 'A')
assert reply.agent == 'Analyst'
assert reply.is_nonempty
assert asdict(reply) == {'agent': 'Analyst', 'content': 'A'}
```

这里定义的是独立教学类，不替换项目的 `AgentResponse`。`asdict` 把 dataclass 转成字典，也会包含 `repr=False` 字段；因此不要对包含 API Key 的 Settings 调用 asdict 后直接输出。`frozen=True` 也不会代替输入验证或递归冻结嵌套数据。

### 7.16 pathlib：路径与文件读取

在项目根目录执行下面的只读例子：

```python
from pathlib import Path

root = Path.cwd()
sample = root / 'docs' / 'samples' / 'd1-logic-proposal.txt'
assert sample.exists()
assert sample.is_file()
assert sample.name == 'd1-logic-proposal.txt'
assert sample.suffix == '.txt'
assert sample.parent.name == 'samples'
text = sample.read_text(encoding='utf-8')
assert '技术方案' in text
assert sample.resolve().is_absolute()
```

`Path.cwd()` 是当前工作目录，不是脚本所在目录；在实际 `.py` 模块中，可用 `Path(__file__).resolve().parent` 找该模块目录。交互解释器里通常没有 `__file__`。

写文件常用 `path.write_text(text, encoding='utf-8')`，它会覆盖已有内容；需要只创建新文件时用 `path.open('x', encoding='utf-8')` 配合 with。生成文件限定在 `mvp/` 内，练习可放 `.tmp/`；不要使用写操作来探测真实 `.env` 内容。

### 7.17 正则：用 fullmatch 检查整个标识

```python
import re

pattern = r'[A-Za-z0-9_-]{1,64}'
assert re.fullmatch(pattern, 'day4-demo_001') is not None
assert re.fullmatch(pattern, 'bad id') is None
assert re.fullmatch(pattern, '') is None
assert re.fullmatch(pattern, 'x' * 65) is None
assert re.fullmatch(pattern, 'valid\n') is None
```

`r'...'` 是原始字符串写法，常用于正则。`fullmatch` 要求整个输入匹配，适合 D4 已实现的 request_id；`search` 只需在任意位置找到一段匹配，不能直接替代标识校验。

### 7.18 查看值、类型与隐藏字符

```python
text = ' A\n'
assert repr(text) == "' A\\n'"
assert type(text).__name__ == 'str'
assert len(text) == 3
assert f'{text!r}' == repr(text)
```

`print(value)` 看面向人的内容；`repr(value)` 或 f-string 的 `!r` 更适合看空格、换行等隐藏字符；`type(value).__name__` 看类型名，`len` 看长度。`help(str.strip)` 可在解释器里查方法帮助，`dir(obj)` 可查看属性名。排查原文坐标时先确认长度与空白，避免顺手修改原文；排查配置时只输出允许显示的字段。

## 8. 测试命令与选择方法

### 8.1 默认回归与定位失败

```bash

# 只跑工作流测试，第一项失败后停止。
```

实际测试数量以终端结果为准。参数化测试会从一个函数生成多项用例，文件中的 `def test_...` 数量不等于 pytest 汇总数量。

当前默认测试使用 Mock、模拟 HTTP 和 Streamlit AppTest 隔离外部模型。通过说明受控场景符合断言，不证明真实凭据、真实网络或模型结论质量。没有执行真实请求时，记录“live 未验证”。

## 11. 常见问题速查

| 现象 | 优先检查 |
| --- | --- |
| `.venv/bin/python` 不存在 | 是否进入 mvp 根目录；是否创建过虚拟环境 |
| `No module named pytest` / `streamlit` | 用本项目解释器安装 `-e '.[test]'`，确认没有用错环境 |
| 教学脚本提示找不到 `review_system` | 在根目录运行；使用表中的 `PYTHONPATH=.`，或先可编辑安装项目 |
| `Set QWEN_API_KEY...` / `Set DEEPSEEK_API_KEY...` | 供应商是否选对、对应 Key 是否为空、是否被已有空环境变量覆盖 |
| `.env` 修改后配置仍不变 | 检查当前终端是否有同名环境变量；必要时在该终端取消对应覆盖后重启 |
| URL 校验失败 | 使用 HTTP(S) 根地址，不带 query/fragment，不重复追加 `/chat/completions` |
| HTTP 401 | 检查所选供应商凭据及账号权限；不把 Key 贴到日志中 |
| 本地 API 返回 429 | capacity_exceeded：服务容量已满；执行中重复标识优先返回 409 |
| 上游 429 | 供应商限流，由本地 API 映射为 502/model_error，不能当作本地容量满 |
| 超时 / HTTP 504 | 区分 network_timeout、model_timeout、total_timeout 与 UI 自身等待超时；不推断供应商已停止 |
| UI 无法连接审核服务 | 先确认 API 已启动，核对 REVIEW_API_BASE_URL；只有 Streamlit 启动不代表后端运行 |
| Critic 失败后没有 Judge | 当前预期行为：后续阶段停止 |
| 回调失败却保留了 Critic | 当前回答先记录，随后调用回调，因此会保留 |
| `unexpected keyword argument 'review_mode'` | 当前 D2 已支持，检查是否运行了旧源码或其他环境中的安装 |
| 找不到 `run_review_async` | D3 已实现，检查是否运行旧源码或错误环境 |
| 找不到 `review_system.api` | D4 已实现，检查工作目录及安装环境 |
| pytest 没跑 D3/D4 脚本 | 它们是独立示例，不是默认测试集；按第 9 节运行 |
| Streamlit 启动后终端不退出 | 服务正在运行，属于正常现象 |

如果确认某个终端的空环境变量覆盖了 `.env`，可只取消这一项，例如 `unset QWEN_API_KEY`，再重新启动应用加载文件中的配置。不要为了排错清空所有环境变量。

## 12. Git：先查看，再精确提交

日常只读检查：

```bash
git status --short
git diff --stat
git diff -- review_system/workflow.py tests/test_workflow.py
git diff --cached
git log -5 --oneline
git check-ignore .env .venv/ .tmp/
```

`git diff` 通常显示已跟踪文件的变更，不会展示未跟踪新文件的全部内容；新文件先在编辑器中打开检查。`git check-ignore` 用于检查忽略规则，不读取文件中的 Key。

需要提交这份指南时，可按下面的顺序操作。这里只提供指令，本次生成指南没有替你执行提交：

```bash
git add -- docs/代码与指令参考指南.md
git diff --cached
git commit -m "docs: add code and command reference"
```

`git commit` 会提交全部已暂存内容，所以提交前检查 `git diff --cached`。若还要提交索引更新，先检查 README 与 docs/README 中是否包含前几日的未提交内容，再决定本次一起提交哪些文件。测试缓存、虚拟环境和真实 `.env` 不纳入提交。

### 13.3 D4 状态码备忘

| HTTP | 本项目当前含义 |
| --- | --- |
| 201 | 审核完成，报告通过契约校验；不要求 Judge 判定方案可通过 |
| 422 | 用户请求不符合契约 |
| 409 | 同一 request_id 的审核仍在执行 |
| 429 | 本地服务容量已满 |
| 502 | 模型调用失败或报告输出不合格 |
| 504 | 网络操作、单模型或审核总预算超时，错误码进一步区分 |
| 500 | 服务内部缺陷 |
| 503 | 服务关闭阶段拒绝新请求 |

供应商 429 映射为本地 API 的 502/model_error；本地容量 429 的错误码为 capacity_exceeded。D4 只防止执行中重复提交；前次结束后再次使用同一 request_id 会重新执行，不保证跨重启幂等或响应丢失后的只执行一次。

## 14. 一次小改动的推荐顺序

1. 确认 `pwd`、解释器和 `git status --short`，找到本次需要修改的模块与测试。
2. 读函数和现有测试，写清触发条件、预期输出、失败时保留什么。
3. 在 `mvp/` 内做最小改动，先跑相关测试，再跑默认 pytest。
4. 如果改变了接口，更新依赖它的课堂脚本和文档，保留历史记录的版本含义。
5. 检查差异，记录实际命令与结果，再按需要精确提交文件。

需要完整讲解时，从 [首日阅读材料](第一日阅读材料.md)或 [文档索引](README.md)进入；需要快速运行、定位和复用代码时，回到本指南对应章节。

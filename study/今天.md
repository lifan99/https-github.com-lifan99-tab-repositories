## 任务 2：找到源码中传递回答的位置

**进入条件：**完成任务 1，保留第二次调用的实际输出。

**目标：**把观察到的 `analyst_output` 对应到真实工作流中的赋值。

打开 [工作流源码](../review_system/workflow.py)，在 `run_review_async` 内只定位下面三处，不通读整个函数：

第一处，建立本次审核的初始材料：

```python
context = {"original_input": request.original_input, "review_mode": request.review_mode}
```

第二处，将当前角色的回答加入材料：

```python
context[f"{agent.name.lower()}_output"] = content
```

这一处先按“把当前角色的名字转成小写，再加 `_output` 作为键名；把当前回答 `content` 存进去”来读，不展开 f-string 的全部语法。

第三处，在角色循环中为每次调用重新生成请求材料：

```python
{"role": "user", "content": json.dumps(context, ensure_ascii=False)}
```

这一行位于 `messages = [...]` 中。先把 `json.dumps(...)` 理解为“把当时的材料字典转成请求文本”。源码里的执行顺序是：生成本轮请求 → 得到回答 → 将回答加入 `context` → 下一轮重新生成请求；上面三处按用途介绍，并非执行顺序。示例客户端再用 `json.loads(...)` 将收到的文本还原成字典，记到 `client.calls` 中。

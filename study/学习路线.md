## 目标与范围

目标是能够解释并实现一个服务：从执行流和 I/O 等待出发，说明网络请求如何进入应用、多个工作如何组织、失败时怎样结束和清理，并为行为设计有效测试。还应能在改变依赖、错误策略或资源归属的新需求中重新应用这些知识。

本轮是两门系统课程与 Python 应用开发之间的桥接课程。CS537 采用 Remzi 的公开 2018 版课程及 OSTEP；UMass Networking 暂按 Kurose/Ross 作者站的 Top-Down 公开课理解。若本人后来指定其他学期或课程，再调整章节对应。

保留前四阶段已完成的本人记录。函数、字典和普通异常属于已有学习经历，具体缺口就地补充；这些记录不直接证明系统基础、async 或 FastAPI 已掌握。

| U7 综合迁移与测试 | 执行、网络、错误边界 → 新需求下的设计与验证 | 独立划分 HTTP、业务和外部调用的职责，编写有区分力的测试，解释实验能证明与不能证明什么 | 先对未演示的新需求设计并实现，再回评审项目定位相关机制；保留稍后回访证据 |

U1 → U2 建立执行与并发基础；U3 → U4 建立通信与接口边界；U5 → U6 将失败处理和资源归属接回服务；U7 整合并检验迁移。基础内容随所依赖的应用单元引入，学习 FastAPI 不需要先完成操作系统的内存管理、文件系统等全部主题。

必要 Python 前置按需补齐：U3 的类型注解和最小类语法；U5 先讲 `with`/`async with` 的进入和退出，再讲 TaskGroup、超时作用域及异常组的最小识别/处理；U6 补充 lifespan 所需的 `yield` 与 `asynccontextmanager`。框架与库的具体行为以本地版本和官方文档核对。

制作后续讲义时，还要在首次使用前补齐以下局部前置，不另开整门语言课程：U2 的可变对象与共享引用，用来判断不同任务是否访问同一份状态；U4 的装饰器及路由注册，区分定义时注册处理函数与收到请求后执行函数；U5 的异常传播与 `try/finally`，再连接取消后的清理。U1 lab 已使用“函数作为参数”，U4 的依赖替换可从这个已有例子衔接；实际掌握仍以本人作答为准。

U1 只需读懂 I/O、同步阻塞、非阻塞与 Task 暂停的区别；Future 内部实现、eager task factory 配置、完整 I/O 分类和具体 CPU 调度算法均不作为当前前置。后续出现实际问题时再展开相应细节。[FastAPI 路由注册](https://fastapi.tiangolo.com/tutorial/first-steps/)、[Python 清理语句](https://docs.python.org/3.12/tutorial/errors.html#defining-clean-up-actions)

## 学习方式与验收

每个单元沿“问题 → 必要模型 → 完整例子 → 连贯实验 → 新条件下的解释/实现”展开。定义、适用条件和反例在当前单元讲全，不把学习过程机械缩成每天修改一行。

- 讲解示例可以完整展示，独立题先留出预测和作答机会；请求提示或完整答案时按实际帮助记录。
- 每个实验明确输入、输出、依赖、允许的顺序和失败策略。并发检查使用必要的先后关系与状态，不把一次观测当成唯一合法调度。
- 异步例子默认 Python 3.12、单个事件循环及默认任务工厂。“事件循环在一个线程运行”不等于整个 Notebook 内核只有一个线程。
- 测试从小断言与状态记录开始，U4 即写接口测试；U7 再组织单元、接口与集成证据。
- 解释与实现证据分开记录。刚看过讲解、获得提示、当场独立完成和稍后迁移分别标明；未做的主题保持未评估。
- 新增“改变依赖、错误策略或资源归属”的检查，并在后续学习日简短回访。局部卡点局部补充，已能解释的部分可直接加深或跳过。
